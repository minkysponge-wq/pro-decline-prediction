# Predicting a Decline in Patient-Reported Outcomes for Cancer Patients on Chemotherapy

**UE24CS352A Machine Learning, Mini-Project, Problem #8 (Sec E, Team E-17)**
Sampreeth Jaladi (PES1UG24AM246) · Sharvesh K (PES1UG24AM260)

A replication of [Ostberg & Peterson, *CS229 Spring 2020*](https://cs229.stanford.edu/proj2020spr/report/Ostberg_Peterson.pdf).
The task: **before the first chemotherapy dose**, predict which patients will report poor physical
health during treatment. Physical health is measured by the PROMIS Global Physical Health (GPH)
T-score (mean 50, SD 10).

| Label | Definition |
|---|---|
| `drop` | on-treatment GPH − baseline GPH ≤ −10 (a decline of ≥ 1 SD) |
| `threshold` | on-treatment GPH ≤ 40 (≥ 1 SD below the population mean) |

> **About the data.** The paper uses de-identified Stanford EHR data (STARR), which is not public.
> This repo therefore includes a **synthetic EHR generator** that produces raw, event-level tables
> with the same structure: patients, encounters, vitals, labs, diagnoses, procedures, medications
> and PROMIS surveys. The paper's full pipeline then runs on those raw tables: cohort selection,
> look-back windows, time-weighting, prevalence filtering, lab imputation and binning, 8 model
> families plus an ensemble, and ablation. The absolute AUROC values describe the simulator, not
> real patients. The point is to reproduce and test the **methodology**.

## Quick start

```bash
git clone <this-repo> && cd pro-decline-prediction
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -e .

python -m prodecline all --fast   # ~5 min: data -> train -> ablation -> figures -> summary
python -m prodecline all          # full paper grids, 10-fold CV (~1 h on 2 cores; resumable)
python -m pytest                  # 22 tests, ~10 s
jupyter notebook notebooks/demo.ipynb   # live demo
```

Each stage can be run on its own, and each one reads the previous stage's outputs from disk:

| Command | What it does | Outputs |
|---|---|---|
| `python -m prodecline data` | simulate EHR → cohort and labels → features → train/test split | `data/raw/*.csv`, `data/processed/*.csv` |
| `python -m prodecline train` | grid search with 10-fold CV for 8 model families plus the ensemble, × 2 outcomes × 2 lab strategies | `results/metrics.csv`, `results/test_predictions.csv`, `results/best_params.json`, `results/models/` |
| `python -m prodecline ablate` | refit the ensemble with each feature group removed | `results/ablation.csv` |
| `python -m prodecline figures` | plots | `results/figures/*.png` |
| `python -m prodecline summary` | print the results table | stdout |
| `python docs/build_writeup.py` | regenerate the 2-page PDF write-up from the results | `docs/writeup.pdf` |
| `python docs/update_readme.py` | regenerate the Results section below | `README.md` |

Options: `--fast` (5-fold CV, small grids), `--fresh` (ignore training checkpoints), `--n-jobs N`, `-v`.
Training is checkpointed per model, so an interrupted run resumes where it stopped.

## Method (paper → code)

**Cohort** (`data/cohort.py`)
- Patients have a cancer diagnosis on or after 2013-01-01.
- The index date is the first chemotherapy administration.
- Each patient needs a baseline PROMIS survey within 90 days before the index date, and an
  on-treatment survey 30–180 days after it.
- The first on-treatment survey defines the label.
- `data/processed/cohort_flow.csv` records how many patients each criterion removes.

**Features** (`features/build.py`). Only events on or before the index date are used.

| Group | Representation |
|---|---|
| `vital` (7) | physiologically impossible readings removed, then an exponentially weighted mean over the last 180 days, weight `exp(−t/365)` |
| `lab` (49) | exponentially weighted mean over 180 days; `NaN` if never measured |
| `proc` | exponentially weighted count over 180 days |
| `dx` | binary, **full history** (the paper keeps old diagnoses) |
| `med` (121 classes) | binary, last 180 days; the chemotherapy class itself is excluded |
| `util` (5) | encounter counts by type over 180 days |
| `demo` | age plus 7 categoricals, one-hot encoded inside the pipeline |
| `promis` (6) | baseline GPH and GMH, days since baseline, number of prior surveys, prior mean, recent change |

**Preprocessing** (`features/preprocess.py`). Every step here is fitted on the training folds only:
- The 2.5% prevalence filter on `lab`, `dx` and `proc`.
- Labs, using one of two strategies:
  - **KNN**: standardise, then `KNNImputer(k=5)`.
  - **binned**: training-set tertiles plus an explicit *missing* bin.
- Constant-column removal, then scaling.

**Models** (`models/registry.py`)
- Logistic regression: LASSO, Ridge and Elastic Net (Ridge λ from 10⁻² to 10⁸; see deviations for LASSO and Elastic Net).
- Random forest and LightGBM.
- MLP with 3 hidden layers, Adam, early stopping after 5 epochs.
- SVM with 4 kernels, C from 10⁻⁴ to 10⁴.
- KNN with k from 1 to 100, uniform or distance weights.
- **Ensemble**: soft vote of the tuned LASSO, Ridge, Elastic Net, RF, LightGBM and SVM (Platt-scaled).

**Evaluation**
- A single stratified 80/20 patient-level split.
- `GridSearchCV` with stratified 10-fold CV on train, scored by AUROC.
- Each best model is refitted on train and scored **once** on test, with a 1,000-sample bootstrap 95% CI.

### Deliberate deviations from the paper
1. **No test-set early stopping.** The paper used the test set to early-stop LightGBM and the MLP,
   which leaks test information. Here LightGBM tunes `n_estimators` in CV, and the MLP early-stops
   on a validation split carved out of each training fold.
2. **Preprocessing fitted inside CV.** The 2.5% filter, imputation and binning cut-points are
   learned per training fold. The paper applied the filter to the whole cohort.
3. **Smaller grids where compute required it.**
   - Random forest uses 500 trees with `max_features ∈ {sqrt, 0.3}` (the paper used 1,000 trees and *all*).
   - Elastic Net uses λ ∈ 10⁰…10³ × 5 L1 ratios (saga converges very slowly for weaker penalties, which never won in pilot runs).
   - LASSO drops λ = 10⁻² (C = 100, effectively unpenalised): liblinear's L1 solver does not converge on near-separable folds of the threshold label.
   - The MLP uses 15 configurations.

   All of these are documented in `registry.py`.

### Correctness safeguards (`tests/`)
- `test_features_identical_without_post_index_events`: the simulator deliberately creates
  post-chemotherapy labs and diagnoses that correlate with the outcome. The test deletes every
  post-index event and checks that the feature matrix is **bit-identical**, which proves no
  future information reaches the model. Breaking the date filter makes this test fail.
- The prevalence filter decides using training rows only.
- Labels match the paper's definitions exactly, and inclusion windows are respected.
- LASSO is genuinely L1-sparse. scikit-learn ≥ 1.8 changed the `penalty` API, and older versions
  silently ignore `l1_ratio`; `registry.logistic()` handles both.
- Every model and the ensemble fit end-to-end, including the ablation case where a whole feature
  group is missing.
- The simulation is deterministic (seed 229).

## Extension: classification accuracy

The paper reports AUROC. We also measured plain **accuracy** and tried to raise it, deciding
everything on training data only. The test set is used once.

```bash
python docs/classification_report.py   # accuracy, precision, recall, F1, confusion matrix
python -m prodecline improve           # burden features + cut-off tuned on training data
python docs/accuracy_ceiling.py        # best accuracy ANY model could reach on this data
```

| Ensemble test accuracy (n = 251) | Drop | Threshold |
|---|---|---|
| Always predict "no" | 81.3% | 77.3% |
| Paper ensemble, default cut-off 0.5 | 81.7% | 82.5% |
| **Paper ensemble, cut-off tuned on training data** | **82.5%** | **84.1%** |
| + burden features, tuned cut-off | 81.7% | 84.1% |
| Theoretical ceiling (a model that knows the hidden frailty) | 83.7% | 83.3% |

- **The tuned cut-off is the change that helps.**
  - With ~20% positives, the default cut-off of 0.5 almost never predicts "yes".
  - We choose the cut-off that maximises accuracy on 10-fold out-of-fold *training* predictions.
  - Threshold recall rises from 25% to 44%.
- **Burden features** (counts of diagnoses, medications, procedures, lab tests and visits, plus
  abnormal prognostic labs at fixed clinical cut-offs, in `features/burden.py`):
  - They raise cross-validated AUROC; for example, Elastic Net on Drop goes from 0.733 to 0.772.
  - Drop test AUROC rises from 0.692 to 0.701.
  - Test accuracy does not change.
- **We are at the ceiling.** The simulator adds unpredictable noise (SD 5.5 points), so even a
  model that knew every hidden variable would reach only ~84% accuracy. Accuracy differences
  of ±1 patient (0.4%) are noise; the 95% CIs are about ±4.5 points.

We deliberately did not pick whichever variant scored best on the test set, because that would
be overfitting to the test set.
